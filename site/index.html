不只是能用的功能

工程细节上做了不少取舍，这里挑最有代表性的几条。

消息中心是算出来的，不是存下来的

逾期待办、临近日程、待打卡、久未备份……六类消息每次都从当前数据实时推导。 待办一勾完，消息自动消失；新逾期待办出现，消息自动多一条。没有陈旧数据要对账。

命令面板，输入即创建

按 ⌘K 模糊搜索待办与笔记，或直接输入一句话回车新建。 「新建」刻意排在结果最后——输入「日历」时回车应该跳转到日历，而不是建一条叫日历的待办。

番茄钟靠时间戳算，不靠定时器累加

剩余时间由开始时刻与结束时刻相减得出，刷新页面或笔记本休眠后依然准确。 中途放弃只结算真正专注过的秒数，不会把一分钟的尝试记成 25 分钟。

重复日程不预生成数据行

每天 / 每周 / 每月的日程在查询时才展开成「发生列表」，跨天事件按天铺开。 数据库里始终只有一条记录，不会随着时间膨胀出几万个副本。

删除是软删除，进回收站保留 7 天

误删的任务可以在回收站里找回来。一键导出 JSON 备份，导入时校验结构， 跨表引用失效的记录会自动修复后再入库。

离线可用，装成应用

手写 Service Worker 缓存应用外壳，断网刷新照样打开。 桌面 Chrome 一键安装到桌面，手机可以「添加到主屏幕」。

想要的话，也能备份到自己的 GitHub

同步默认关闭，不开就一个字节都不出浏览器。开了之后数据只发往你指定的那个仓库， 令牌还能限定到这一个仓库——相当于一个可版本控制的备份，顺便能在设备之间搬数据。

技术选型

全部依赖克制在必要范围内，不引入组件库。

features/*  ──useLiveQuery──►  db/repositories/*  ──►  Dexie / IndexedDB
     └──useUIStore──►  Zustand persist  ──►  localStorage

一条硬约束：组件不允许直接 import db，所有读写必须走仓储层。 这样统计口径统一、可单测，将来要接后端只需新增一套实现，界面零改动。

本地跑起来

需要 Node 20+ 与 pnpm。

1
pnpm install

安装依赖

2
pnpm dev

启动开发服务器，打开 http://127.0.0.1:5273/workbench/

3
pnpm build

类型检查 + 生产构建到 dist/

首次打开会灌入一批示例数据 让主页立刻是「活的」而不是一片空白。想从零开始，用顶栏的「数据 → 清空本地数据」，之后不会再自动播种。
